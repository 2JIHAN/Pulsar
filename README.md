# Pulsar 0.8.0

두 Mac 사이에서 기본 디스플레이 화면을 보고 마우스와 키보드를 제어하는 독립 macOS 앱입니다. 기존 ThunderControl과 Parsec의 설정이나 세션을 사용하지 않습니다. macOS 14 이상과 Apple Silicon이 필요합니다.

## 빌드하고 검사하기

```sh
cd /Users/seesoong/workspace/RemoteControl
./build.sh
./build/Pulsar.app/Contents/MacOS/Pulsar --self-test
open build/Pulsar.app
```

결과는 `build/Pulsar.app`입니다. 앱은 개발용 ad-hoc 서명이며 Apple 공증은 없습니다. `/Applications`에 설치하지 않습니다. 자체 테스트는 화면 기록이나 기기 제어 및 데이터 접근 권한 없이 실행할 수 있습니다. 테스트의 입력 이벤트는 테스트용 함수로 받아 실제 시스템에 주입하지 않습니다.

## 같은 Tailscale 계정의 Mac에 바로 연결하기

1. 두 Mac에 Pulsar 0.6.0 이상을 설치하고 같은 Tailscale 계정으로 로그인합니다.
2. 화면을 공유할 Mac에서 Pulsar를 엽니다. **설정 > 일반 > Pulsar 실행 시 자동으로 공유 시작**이 기본으로 켜져 있어 화면 기록 권한이 있으면 바로 공유를 시작합니다. **로그인 시 Pulsar 실행**을 켜 두면 재시동 후에도 공유합니다.
3. 다른 Mac의 **컴퓨터** 목록에서 상태가 **공유 중**인 Mac의 **연결**을 누릅니다. 연결코드는 필요 없습니다.

목록은 10초마다 Tailscale 기기를 다시 읽습니다. `tailscale status --json`의 피어 정보(`CurAddr`, `Relay`)로 경로(Tailscale 직접, Tailscale 중계 또는 Tailscale)를 판단하고, 온라인 macOS 기기의 포트 47700에 TCP 연결을 시도해 공유 여부를 확인합니다. 다른 계정 소유 기기는 **다른 계정**으로 표시하고 연결 버튼을 두지 않습니다. 이런 Mac에는 아래 연결코드 방식으로 접속합니다.

## 연결코드로 연결하기 (LAN 또는 다른 계정)


1. 두 Mac에 같은 앱을 빌드하거나 복사합니다.
2. 화면을 공유할 Mac에서 **호스트 시작**을 누릅니다. 화면 기록 권한이 거부되면 시스템 설정의 **개인정보 보호 및 보안 > 화면 및 시스템 오디오 기록**에서 Pulsar을 허용하고 앱을 다시 엽니다. macOS 버전에 따라 항목 이름이 다를 수 있습니다.
3. 내부망에서는 **LAN** 주소를 선택합니다. 외부망에서는 두 Mac을 같은 Tailscale 네트워크에 연결하고 **Tailscale** 주소를 선택합니다. 호스트의 현재 Tailscale 주소는 `100.116.229.75`로 확인되었습니다. 앱은 실제 인터페이스 주소를 열거하며 이 주소를 고정하지 않습니다.
4. **연결코드 복사**를 누르고 신뢰할 수 있는 경로로 상대에게 전달합니다. 이 코드에는 주소, 포트와 비밀키가 함께 들어 있습니다. 코드를 가진 사람은 화면을 볼 수 있으므로 공개하지 마세요. 복사한 코드는 시스템 클립보드에 남습니다.
5. 상대 Mac에서 코드를 비밀번호 형태로 가려진 입력 칸에 붙여넣고 **접속**을 누릅니다. 접속을 시작하면 입력 칸의 코드는 지웁니다.
6. 원격 조작이 필요하면 호스트에서 **원격 마우스와 키보드 허용**을 체크합니다. 기기 제어 및 데이터 접근 권한이 없으면 안내에 따라 허용한 뒤 다시 체크합니다. 이 옵션은 기본으로 꺼져 있습니다.
7. 뷰어 화면을 클릭하면 키보드와 마우스 입력을 전달합니다. 화면 밖 여백의 클릭은 전달하지 않습니다. 다른 창으로 이동하거나 입력 칸으로 초점을 옮기면 원격으로 눌린 키와 버튼을 해제합니다.
8. **긴급 중지 (모든 연결)** 또는 뷰어에 초점이 있을 때 `Command+Option+Escape`로 중지합니다. macOS가 이 키 조합을 먼저 처리하면 화면의 중지 버튼을 사용합니다. 호스트 중지 후 다시 시작하면 새 비밀키를 만듭니다.

로컬 네트워크 접근 권한이 표시되면 연결할 Mac에 접근할 수 있도록 허용해야 합니다. macOS 방화벽이 묻는 경우 사용자가 수신 연결 허용 여부를 결정해야 합니다. 앱이 방화벽이나 TCC 권한을 자동으로 변경하지 않습니다. Tailscale ACL도 해당 TCP 연결을 허용해야 합니다. 별도 포트 전달이나 인터넷에 직접 포트 공개는 권장하지 않습니다.

## 0.3.0 변경 사항

- **자동 재연결.** 사용자가 **뷰어 연결 해제**나 긴급 중지를 누르지 않았는데 연결이 끊기면 뷰어가 2초마다 다시 접속합니다. 최대 2분 동안 시도하며 상태 줄에 `재연결 중… (n회)`를 표시합니다. 그동안 마지막 화면을 유지합니다. 비밀키가 맞지 않아 TLS 인증이 실패하면 재시도하지 않고 `연결코드가 맞지 않습니다`를 표시합니다.
- **편집 메뉴.** 오려두기, 복사하기, 붙여넣기, 전체 선택 메뉴를 추가했습니다. 연결코드 칸에 `Command+V`로 붙여넣을 수 있습니다.
- **단축키 전달.** 연결 중 뷰어에 초점이 있으면 `Command+Q`, `Command+W`, `Command+V` 같은 앱 단축키를 원격 Mac으로 보냅니다. `Command+Tab`, `Command+Space`, `Control+화살표` 같은 시스템 단축키는 이 Mac(뷰어)에 기기 제어 및 데이터 접근 권한이 있을 때만 시스템 단축키를 잠시 끄고 전달합니다. 권한이 없으면 상태 줄에 안내만 표시하고 권한을 반복해서 요청하지 않습니다. 뷰어 초점을 잃거나 창이나 앱이 비활성화되거나 연결이 끊기면 시스템 단축키를 바로 되돌립니다.
- **트랙패드 제스처.** 핀치, 회전, 스와이프와 스마트 확대를 원격 Mac에 전달합니다. 원래 이벤트 데이터를 그대로 재생하므로 두 Mac의 macOS 빌드 번호가 같아야 합니다. 빌드가 다르면 호스트가 제스처를 무시하고 상태 줄에 한 번 알립니다. 연결이 끊길 때 진행 중이던 제스처의 종료 이벤트는 만들지 않습니다. 세 손가락이나 네 손가락으로 데스크톱을 전환하거나 Mission Control을 여는 동작은 Dock이 처리하는 시스템 제스처라 앱에 전달되지 않으므로 지원하지 않습니다.

## 보안과 제한

- **Tailscale 계정이 곧 접근 권한입니다.** 공유가 켜져 있으면 같은 Tailscale 계정으로 로그인한 기기(휴대폰 포함)는 화면을 볼 수 있습니다. 마우스와 키보드 입력은 **설정 > 일반 > 다른 Mac이 이 Mac을 조작하도록 허용**과 기기 제어 및 데이터 접근 권한으로 따로 통제합니다. 허용 여부는 저장되며, 다음 실행 때 권한이 있을 때만 다시 켭니다.
- 바로 연결은 TLS 없이 Tailscale 주소(100.64.0.0/10)에만 바인드한 TCP 포트 47700을 씁니다. 암호화와 기기 인증은 Tailscale(WireGuard)이 맡습니다. 호스트는 데이터를 읽기 전에 `tailscale whois --json <상대 IP>`(2초 제한)로 상대 기기의 소유 계정을 확인하고, 자기 계정(`tailscale status --json`의 Self 사용자)과 같을 때만 받습니다. whois 실패, 해석 실패, 자기 계정 미확인은 모두 거부합니다. LAN 주소에서는 이 포트가 열리지 않습니다. 같은 Mac의 다른 프로세스가 자기 Tailscale 주소로 접속하면 같은 계정으로 판정됩니다.
- 수락된 연결도 양쪽이 hello를 주고받은 뒤에만 세션이 됩니다. 컴퓨터 목록의 포트 확인처럼 TCP 연결만 하고 끊는 접속은 기존 세션을 바꾸지 않고 조용히 닫힙니다. 뷰어는 호스트가 hello 전에 연결을 3번 연속 닫으면 재시도를 멈추고 `상대 Mac이 이 계정의 연결을 거부했습니다`를 표시합니다.
- 연결코드 방식은 그대로입니다. TLS 1.2와 `TLS_ECDHE_PSK_WITH_CHACHA20_POLY1305_SHA256` 한 암호군을 사용합니다. 호스트 세션마다 보안 난수 32바이트 PSK를 생성합니다. 실제 루프백 테스트에서 협상된 버전과 암호군을 검사합니다.
- TLS 인증 전에 화면이나 입력을 처리하지 않습니다. 잘못된 키는 실제 TLS bad-MAC 오류로 거부합니다. 평문이나 약한 암호군으로 재시도하지 않습니다. 연결코드와 비밀키는 로그로 출력하지 않습니다.
- 공유가 켜져 있는 동안만 수신합니다. 인증된 클라이언트는 한 개만 유지합니다. 동시에 진행하는 연결은 최대 세 개이며, TLS 핸드셰이크 제한은 8초입니다. 두 초마다 heartbeat를 보냅니다. 호스트는 20초, 뷰어는 6초 이상 수신이 없으면 연결을 정리합니다. 같은 비밀키로 새 뷰어가 인증되면 호스트는 기존 연결을 닫고 새 연결로 화면 전송을 다시 시작합니다.
- 메인 디스플레이 한 개를 최대 1920×1200, 초당 최대 30프레임의 H.264 하드웨어 인코딩(평균 6Mbps, 최대 9Mbps, 2초마다 키프레임)으로 전송합니다. 인코딩된 프레임은 버리지 않고, 전송 중인 프레임이 두 개면 인코딩 전에 캡처 프레임을 건너뜁니다. 수신 측은 디코딩 전에 SPS의 해상도와 메시지 구조를 검사합니다. 0.1.0(JPEG)과는 호환되지 않습니다.
- 외부망 연결은 기존 Tailscale 암호화 네트워크를 이용합니다. 자체 NAT 우회, STUN, TURN 또는 계정 서버는 구현하지 않았습니다.
- 파일, 클립보드 동기화, 오디오와 가상 디스플레이는 없습니다. 물리 키코드를 전송하므로 두 Mac의 키보드 배열과 입력기 차이가 영향을 줄 수 있습니다. 잠금 화면과 보안 입력은 정상 제어를 보장하지 않습니다.
- Parsec과 같은 성능이나 지연시간을 보장하는 제품이 아닙니다. H.264 기반 기본형입니다. 화면 기록과 원격 입력의 권한 승인 후 실제 두 장치 LAN 및 WAN 제어 검증은 아직 하지 않았습니다.

## 코드 구조

`Protocol.swift`는 연결코드, 메시지 경계와 TLS를 담당합니다. `Capture.swift`는 ScreenCaptureKit과 입력 주입을 담당합니다. `App.swift`는 호스트 수명, 세션 상태와 초점이 있는 뷰어를 담당합니다. `Pages.swift`는 사이드바, 컴퓨터, 연결코드, 설정 화면과 세션 상단 보드를 담당합니다. `Tests.swift`는 실제 프로토콜과 TLS 루프백을 검사합니다.

구조 대안은 별도 호스트/뷰어 앱과 한 앱의 두 역할이었습니다. 배포와 세션 상태가 적은 한 앱 구조를 선택했습니다. Model the Domain 원칙에 따라 입력 종류를 enum과 검증되는 메시지로 표현했습니다. Laziness Protocol에 따라 기존 대형 프로젝트를 복제하지 않고 필요한 기능만 분리했습니다. Prove It Works에 따라 빌드뿐 아니라 실제 TLS 왕복과 잘못된 키 차단을 검사합니다.

## 빌드 파일의 격리 속성 자동 정리

빌드 스크립트는 컴파일과 서명을 마친 뒤 `scripts/clear-quarantine.sh`로 앱 전체의 격리 속성을 제거하고 검증합니다. 실패하면 빌드도 실패 처리하며 앱을 실행하면 안 됩니다. 다른 확장 속성은 보존하고 심볼릭 링크의 대상을 따라가지 않습니다.

이 Mac에는 앱 전용이 아닌 `Aside-생성파일-격리자동정리` 공통 LaunchAgent가 설치돼 있습니다. 새 파일 변경 이벤트에서 출처가 정확히 Aside인 격리 속성만 정리합니다. 기존 파일의 전체 순회는 하지 않고, 다른 앱 출처 태그는 보존합니다. 비동기 이벤트 처리이므로 빌드 직후의 검사 단계를 대체하지 않습니다. Pulsar 전용 감시기는 비활성화했습니다. 현재 공통 처리기 안내는 `/Users/seesoong/background/aside-quarantine-guard/README.md`에 있습니다. 공통 서비스 설치는 앱이나 소스를 다른 Mac에 복사하는 것만으로 따라가지 않습니다.

## 0.3.1 변경 사항

- Ctrl+위 화살표(Mission Control) 같은 시스템 단축키가 뷰어 Mac에서 먼저 실행되던 문제를 고쳤습니다. Parsec과 같은 방식으로 뷰어에 초점이 있는 동안 시스템 단축키를 끕니다.
- 뷰어 Mac에는 기기 제어 및 데이터 접근과 입력 모니터링 권한이 필요합니다.

## 0.3.2 변경 사항

- Pulsar > 환경설정(Command+,)에서 화면 기록, 기기 제어 및 데이터 접근, 입력 모니터링 권한의 허용 여부를 확인하고 각 설정 화면을 바로 열 수 있습니다.

## 0.3.3 변경 사항

- 입력 모니터링 상태를 "허용됨" 대신 "사용 가능"으로 표시합니다. macOS는 기기 제어 및 데이터 접근이 허용된 앱을 입력을 읽을 수 있는 앱으로 판단하므로, 입력 모니터링 목록에 Pulsar가 없어도 사용 가능으로 나올 수 있습니다.

## 0.3.4 변경 사항

- macOS 27의 권한 이름에 맞춰 "손쉬운 사용"을 "기기 제어 및 데이터 접근"으로 표기합니다. 시스템 설정 > 개인정보 보호 및 보안 > 기기 제어 및 데이터 접근에서 허용합니다.

## 0.4.0 변경 사항

- 창을 사이드바(컴퓨터, 연결코드, 설정)와 본문으로 다시 구성했습니다. 사이드바 아래에서 공유 상태를 보고 공유를 시작하거나 중지합니다. 버튼 이름은 "호스트 시작" 대신 "공유 시작"입니다.
- **컴퓨터**: Tailscale CLI(`status --json`)로 같은 tailnet의 기기를 10초마다 불러와 기기, 경로, 지연, 상태를 표로 보여 줍니다. 지연은 아직 측정하지 않아 "—"로 표시합니다. 목록의 **연결** 버튼은 아직 바로 접속하지 않고 연결코드 화면으로 안내합니다. 아래 "이 Mac" 줄에서 원격 입력 허용과 세 권한 상태를 확인합니다.
- **설정**(Command+,): 별도 권한 창을 없애고 권한, 단축키, 화면 항목을 한 화면에 모았습니다. 단축키 세 개(연결 종료, 오버레이 메뉴, 전체 화면)와 "시스템 단축키를 원격으로 보내기"는 기록하고 저장만 합니다. 실제 동작은 다음 버전에서 연결합니다.
- **세션**: 접속하면 원격 화면이 창 전체를 채우고 사이드바를 숨깁니다. 접속 직후 3초 동안, 그리고 포인터를 원격 화면 맨 위로 올리면 상단 보드에 상대 기기, 초당 프레임, 수신 Mbps, 전체 화면과 연결 종료 버튼이 나타납니다. 재연결 중에는 보드에 `재연결 중… (n회)`를 표시합니다.

## 0.5.0 변경 사항

- **목록에서 바로 연결.** 같은 Tailscale 계정의 Mac은 컴퓨터 목록의 **연결** 한 번으로 접속합니다. 공유하지 않는 Mac의 연결 버튼은 꺼지고 "상대 Mac에서 공유를 켜 주세요"를 보여 줍니다. 공유 중에도 다른 Mac에 접속할 수 있습니다.
- **실제 상태와 지연.** 상태 열은 공유 중(빨간 점), 공유 안 함, 오프라인, 다른 계정, 지원 안 함을 보여 줍니다. 지연과 경로는 `tailscale ping` 결과입니다. 세션 상단 보드에도 같은 지연을 표시합니다.
- **자동 공유와 로그인 항목.** 설정 > 일반에서 실행 시 자동 공유(기본 켬)와 로그인 시 실행(SMAppService)을 바꿉니다. 원격 입력 허용 상태를 저장합니다. 공유를 중지해도 원격 입력 허용은 끄지 않습니다.
- **단축키 동작.** 원격 화면을 보는 동안 연결 종료(기본 ⌃⌥⌘D), 오버레이 메뉴(⌃⌥⌘O, 상단 보드 고정과 해제), 전체 화면(⌃⌥⌘F)을 이 Mac에서 처리하고 상대 Mac에는 보내지 않습니다. 단축키 기록은 ⌃, ⌥, ⌘가 없는 조합과 다른 동작이 쓰는 조합을 거부합니다. **시스템 단축키를 원격으로 보내기**를 끄면 시스템 단축키를 끄지 않아 ⌘Tab 등이 이 Mac에서 실행됩니다. ⌘⌥⎋ 긴급 중지는 그대로입니다.

## 0.6.0 변경 사항

- **연결 종료 단축키 변경.** 기본값을 `⌃⌥⇧Q`로 바꾸고 기존 기본값(`⌃⌥⌘D`)이 저장돼 있으면 첫 로드 시 새 기본값으로 옮깁니다. 단축키 기록은 `⇧`를 포함한 조합을 받으며 `⌃`, `⌥`, `⌘` 중 하나 이상을 요구합니다.
- **사이드바와 컴퓨터 화면 정리.** 사이드바 아래 공유 상태와 시작/중지 버튼을 없애고 앱 버전을 표시합니다. **컴퓨터** 아래 막대를 없애고 **다른 Mac이 이 Mac을 조작하도록 허용** 스위치를 **설정 > 일반**으로 옮겼습니다. **컴퓨터**에서는 필요한 권한이 빠져 있을 때만 제목 아래 안내 줄과 **설정 열기** 버튼을 보여 줍니다.
- **입력 모니터링 실제 확인.** IOKit의 `IOHIDCheckAccess`/`IOHIDRequestAccess`로 입력 모니터링 권한을 확인하고 실행 시 및 **설정 열기**에서 요청합니다. 상태 표기는 **허용됨**과 **허용 안 됨**만 씁니다.
- **지연 측정 제거.** 주기적인 `tailscale ping`과 장치 표의 지연 열, 세션 상단 보드의 지연 표시를 없앴습니다. 경로는 `tailscale status --json`의 `CurAddr`과 `Relay` 필드로 판별하고, 포트 47700 공유 확인은 유지합니다.

## 0.7.0 변경 사항

- **뷰어 화면 품질 설정.** **설정 > 화면 품질**에서 코덱(자동/H.264/HEVC), 색상(표준 4:2:0 / 선명한 글자 4:4:4, HEVC 전용), 비트레이트(자동 8 Mbps ~ 50 Mbps, 최대 대역폭 평균의 1.5배), 최대 해상도(1080p / 1440p / 원본 최대 3840×2400), 프레임(30 / 60 fps)을 선택합니다. 접속 시 뷰어가 요청을 보내고 호스트가 하드웨어 지원에 맞춰 적용한 결과를 세션 상단 보드와 **최근 연결** 줄에 표시합니다. 구버전 뷰어는 1초 후 기본값(H.264, 8 Mbps, 1920×1200, 30 fps)으로 연결됩니다.
- **입력 모니터링 안내.** macOS가 기기 제어 권한을 통해 허용으로 응답하는 경우를 구분해 **입력 모니터링** 상태를 **직접 확인 필요**로 표시하고, **컴퓨터** 제목 아래 누락 권한 경고에서 제외했습니다.

## 0.8.0 변경 사항

- **설정 > 일반 통합.** 기존 자동 공유 시작과 원격 조작 허용 스위치를 **이 Mac 원격 접속 허용**(기본 켬) 하나로 통합했습니다. 이전 버전의 두 설정 중 하나라도 켜져 있었으면 켬 상태로 옮깁니다.
- **연결코드 게스트 권한 분리.** 같은 Tailscale 계정(`whois` 검증) 접속은 화면과 마우스·키보드를 모두 허용하고, 연결코드(TLS-PSK) 접속은 기본적으로 보기 전용으로 제한합니다. **연결코드** 화면의 **연결코드 접속자에게 마우스·키보드 허용**(기본 끔)으로 제어 여부를 따로 켭니다.
- **잠자기 방지.** **설정 > 일반 > 잠자기 방지**(기본 켬)를 켜 두면 공유가 켜져 있는 동안 `IOPMAssertion`(`kIOPMAssertionTypePreventUserIdleSystemSleep`, `"Pulsar hosting"`)을 유지하고, 공유 중지나 앱 종료 시 해제합니다.
- **접속 시 가상 디스플레이.** **설정 > 화면 품질 > 접속 시 가상 디스플레이 사용**(기본 켬)이 켜져 있으면 호스트가 뷰어 화면 크기에 맞춘 가상 디스플레이를 생성해 해당 화면만 전송하고 호스트의 실제 화면은 그대로 둡니다. 적용 시 세션 상단 보드에 **가상 화면**을 표시하며, 생성에 실패하거나 API가 없으면 기본 디스플레이로 대체합니다. 이 기능은 비공개 `CGVirtualDisplay` API를 사용하므로 향후 macOS 업데이트에서 동작이 깨질 수 있습니다(Parsec, ThunderControl도 같은 비공개 API를 사용합니다).
